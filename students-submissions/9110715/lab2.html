5. Text Feature Extraction Using CountVectorizer¶

Machine learning classifiers require numerical features rather than raw text.

CountVectorizer converts each email into a numerical representation based on word frequencies.

The following preprocessing settings are used:

  • Convert text to lowercase (default behavior).
  • Remove common English stop words.
  • Keep a maximum of 2,000 features.
  • Ignore words appearing in fewer than two training emails.

The vectorizer is fitted only on the training data to prevent information leakage from the test dataset.

The same numerical features will be used to train and compare Gaussian Naive Bayes and Multinomial Naive Bayes classifiers.

In [5]:
from sklearn.feature_extraction.text import CountVectorizer

# Initialize text vectorizer
vectorizer = CountVectorizer(
    max_features=2000,
    min_df=2,
    stop_words="english"
)

# Learn vocabulary from training data only
X_train_counts = vectorizer.fit_transform(X_train)

6. Training Naive Bayes Classification Models¶

Naive Bayes is a probabilistic machine learning algorithm based on Bayes' theorem. It assumes that features are conditionally independent given the class label.

Two classifiers are trained and compared:

Gaussian Naive Bayes

Gaussian Naive Bayes assumes that numerical features follow a normal distribution within each class.

Multinomial Naive Bayes

Multinomial Naive Bayes is designed for discrete count-based features, making it suitable for text classification using word frequencies.

Both models are trained using the same training dataset to ensure a fair comparison.

Gaussian Naive Bayes requires a dense feature matrix, while Multinomial Naive Bayes supports sparse matrices.

The trained models will be evaluated using the previously separated test dataset.

In [6]:

7. Model Evaluation and Comparison¶

Both Gaussian Naive Bayes and Multinomial Naive Bayes are evaluated using the same 999 testing emails.

The following evaluation metrics are used:

  • Accuracy: Overall percentage of correct predictions.
  • Precision: Proportion of predicted spam emails that are actually spam.
  • Recall: Proportion of actual spam emails correctly detected.
  • F1-score: Harmonic mean of precision and recall.
  • Confusion Matrix: Shows correct and incorrect classifications.

Since the dataset contains more ham than spam, accuracy alone may be misleading.

The models will be compared using all these metrics to determine which performs better for spam detection.

In [7]:

The following statistical measures are calculated:

  • Mean: Average nightly price.
  • Median: Middle nightly price.
  • Standard Deviation: Variation in prices.

No outliers are removed at this stage.

4. Outlier Detection Using the IQR Method¶

The Interquartile Range (IQR) measures the spread of the middle 50% of the data.

IQR = Q3 - Q1

The standard 1.5 × IQR rule defines the boundaries:

  • Lower Bound = Q1 - 1.5 × IQR
  • Upper Bound = Q3 + 1.5 × IQR

For the original Airbnb prices:

  • Q1 = $69
  • Q3 = $175
  • IQR = $106
  • Lower Bound = -$90
  • Upper Bound = $334

Prices outside these boundaries are flagged as potential statistical outliers.

Before applying the method, zero or negative prices are excluded because the analysis concerns paid nightly accommodation.

The IQR method is relatively resistant to extreme values because it uses quartiles instead of the mean.

5. Outlier Detection Using Mean, Standard Deviation,¶

and Z-Score

The Z-score measures how far an observation is from the mean in units of standard deviation.

The formula is:

$$ Z = \frac{x - \mu}{\sigma} $$

Where:

  • x = Individual nightly price
  • μ = Mean nightly price
  • σ = Standard deviation

For this analysis, prices with an absolute Z-score greater than 3 are considered potential outliers.

This method uses the mean and standard deviation to identify unusually high or low nightly prices.

Limitation:

The Airbnb prices are strongly right-skewed. Extremely expensive listings influence both the mean and standard deviation, potentially making the Z-score method less effective at identifying moderately high-price outliers.

The results will be compared with the IQR method.

6. Outlier Detection Using Median Absolute Deviation (MAD)¶

Median Absolute Deviation (MAD) is a robust statistical measure of dispersion.

Unlike standard deviation, MAD uses the median as its central reference point.

The formula is:

$$ MAD = \operatorname{median}(|x_i - \operatorname{median}(x)|) $$

A modified Z-score is calculated as:

$$ M_i = \frac{0.6745(x_i - \operatorname{median}(x))}{MAD} $$

Observations with an absolute modified Z-score greater than 3.5 are flagged as potential outliers.

Why use MAD?

Airbnb prices are strongly right-skewed. MAD is less sensitive to extremely expensive listings than the mean and standard deviation.

This method provides another way to identify unusual nightly prices without relying on a normal distribution.

In [14]:
# -------------------------------------

# -------------------------------------

    df_valid["price"] - median_price
).abs()

print(f"Median Price: ${median_price:.2f}")
print(f"Median Absolute Deviation: ${mad:.2f}")

# 2. Calculate modified Z-scores
# -------------------------------------

    raise ValueError("MAD is zero; this method cannot be applied.")

    0.6745 * (df_valid["price"] - median_price) / mad
)

    "Percentage Removed:",
    round(len(df_mad_outliers) / len(df_valid) * 100, 2),
    "%"
)

# -------------------------------------
# 4. Calculate original MAD boundaries
# -------------------------------------

7. Outlier Detection Using Percentiles¶

Percentile-based filtering identifies unusually low and high prices using selected percentile boundaries.

For this analysis:

  • Lower boundary: 1st percentile
  • Upper boundary: 99th percentile

Prices below the 1st percentile or above the 99th percentile are flagged as potential outliers.

Advantages:

  • Easy to calculate and understand.
  • Does not assume a normal distribution.
  • Limits the influence of extreme prices.

Limitations:

  • The percentile thresholds are subjective.
  • Genuine low-cost and luxury listings may be excluded.
  • Percentile filtering does not guarantee that the resulting data contains no outliers under other statistical definitions.

The results will be compared with IQR, Z-score, and Median Absolute Deviation (MAD).

9. Room-Type-Based Outlier Detection¶

Airbnb listings contain different types of accommodation, including entire homes, private rooms, and shared rooms.

These accommodation types have different typical prices.

Applying one global price boundary may incorrectly classify legitimate expensive apartments as outliers.

To address this limitation, the IQR method is applied separately within each room type.

For each room type:

  1. Calculate Q1 and Q3.
  2. Calculate the IQR.
  3. Determine lower and upper outlier boundaries.
  4. Identify listings outside those boundaries.
  5. Create a cleaned dataset.

This approach considers differences between accommodation categories.

However, statistical outliers may still represent legitimate premium or unusually inexpensive listings.

In [17]:
# -------------------------------------
# 1. Calculate IQR boundaries by room type
# -------------------------------------

room_type_stats = (
    df_valid.groupby("room_type")["price"]
    .agg(
        count="count",
        Q1=lambda x: x.quantile(0.25),
        median="median",
        Q3=lambda x: x.quantile(0.75)
    )
)

room_type_stats["IQR"] = (
    room_type_stats["Q3"] - room_type_stats["Q1"]
)

room_type_stats["Lower Bound"] = (
    room_type_stats["Q1"] - 1.5 * room_type_stats["IQR"]
)

room_type_stats["Upper Bound"] = (
    room_type_stats["Q3"] + 1.5 * room_type_stats["IQR"]
)

print("IQR Boundaries by Room Type:")
display(room_type_stats.round(2))


# -------------------------------------

# -------------------------------------

df_room_iqr = df_valid.join(
    room_type_stats[["Lower Bound", "Upper Bound"]],
    on="room_type"
)

room_outlier_mask = (
    (df_room_iqr["price"] < df_room_iqr["Lower Bound"]) |
    (df_room_iqr["price"] > df_room_iqr["Upper Bound"])
)

The room-type-based method calculates separate outlier boundaries for each accommodation category.

This approach better accounts for differences in accommodation prices.

12. Part B — Final Conclusion¶

In Part B, the New York City Airbnb dataset was analyzed to identify and remove unusual nightly prices using statistical measures of central tendency and dispersion.

Dataset Exploration¶

The original dataset contained 48,895 listings and 16 columns.

The mean nightly price was $152.72, while the median was $106. This difference indicated a strongly right-skewed price distribution.

The original maximum price was $10,000.

Eleven listings with zero nightly prices were excluded because the analysis focused on paid accommodation.

Outlier Detection Methods¶

Five statistical approaches were demonstrated:

Method Outliers Detected
Global IQR 2,972
Z-score 388
Median Absolute Deviation (MAD) 2,916
1st–99th Percentiles 867
Room-Type-Based IQR 3,244

All five methods were applied to the same 48,884 valid-price listings.

IQR and MAD identified more high-price outliers than the Z-score method because they are less sensitive to extreme values.

Percentile filtering identified both unusually low and high prices.

Selected Cleaning Method¶

Room-type-based IQR was selected because entire homes, private rooms, and shared rooms have different typical nightly prices.

Instead of applying one price boundary to all listings, this method calculates separate IQR boundaries for each accommodation type.

The method removed 3,244 statistical outliers from the valid-price dataset.

Final Cleaned Dataset¶

The final dataset contains:

  • 45,640 Airbnb listings
  • 16 original columns
  • Minimum nightly price: $10
  • Maximum nightly price: $392
  • Mean nightly price: $121.81
  • Median nightly price: $100
  • Standard deviation: $73.23

A total of 3,255 records were excluded from the original dataset, including 11 zero-price listings.

The cleaned dataset was exported as airbnb_cleaned.csv.

Limitations¶

Statistical outliers are not necessarily incorrect observations. Some expensive Airbnb listings may represent legitimate luxury accommodation.

The final dataset satisfies the original room-type-specific IQR boundaries.

However, recalculating statistical boundaries on the cleaned dataset may identify additional outliers.

Missing review information was retained because it was not required for price outlier analysis.

Final Observation¶

This analysis demonstrates how the mean, median, standard deviation, quartiles, percentiles, and robust statistical techniques can be used to investigate unusual values.

Selecting an appropriate outlier-detection method requires considering the distribution of the data and the context of the observations.
